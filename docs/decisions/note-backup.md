# 전체 백업과 복원

## Decisions

- 아무노트 전용 백업 하나에 서버에 저장된 보관함 전체를 담는다. 폴더 구조, 세 형식의 제목·본문·서식·그림 요소, 고정 상태, 노트 배경 이미지, 휴지통 항목, 현재 보관 중인 수정 이력을 포함한다.
- 복원은 로그인한 계정에 새 복사본을 추가한다. 기존 자료는 고치거나 지우지 않는다. 같은 이름도 덮어쓰지 않으며, 보관함 뿌리의 새 복원 폴더 아래에 원래 구조를 넣는다.
- 새 식별자로 원본과 복사본을 분리한다. 휴지통 항목은 휴지통 상태로, 이력은 해당 복사본의 이력으로 유지한다. 다른 계정에 복원해도 배경 이미지는 복원한 계정의 비공개 보관소에 복사한다.
- 계정·로그인 정보와 현재 계정 설정은 복원 대상이 아니다. 공유 링크는 백업에 담지 않고 복원한 노트는 공유를 끈 상태로 시작한다.
- 복원 전에 파일과 포함 항목 수를 확인한다. 읽지 못하는 파일이나 불완전한 백업은 쓰기 전에 거절하고, 폴더·노트·이력은 함께 반영한다. 응답을 받지 못한 복원 요청을 다시 시도해도 같은 요청의 복사본이 중복 생성되지 않는다.

## Boundaries

- 백업은 서버에 저장된 상태를 담는다. 현재 브라우저의 미저장 초안은 별도 보호 대상이다. 내보내는 시점에 이 차이를 알린다.
- 개별 HTML·Markdown·SVG 파일이나 외부 앱 자료 가져오기, 형식 변환, 기존 보관함 교체·자동 병합은 범위 밖이다.
- 백업은 암호화된 금고가 아니다. 사용자가 받은 파일에는 자신의 노트 내용이 담긴다.

## Why

개별 내보내기만으로는 폴더와 수정 가능한 그림 요소·배경·이력을 한 번에 되살릴 수 없다. 전용 백업으로 앱의 상태를 보관하되 계정과 공유 권한은 옮기지 않으면 다른 계정에서도 자신의 자료를 이어 쓸 수 있다.

복원을 덮어쓰기로 만들면 백업 이후에 쓴 내용이나 같은 이름의 다른 노트를 잃을 수 있다. 2026-11-01 사용자가 원본 유지와 별도 복사본 추가를 선택했다. 새 폴더는 복원한 범위를 눈으로 확인하고 필요하면 한 번에 정리할 수 있게 한다.

## Reconsider when

- 복원본을 기존 자료와 합쳐 정리하는 비용이 커져 명시적인 병합 요구가 생길 때.
- 외부 앱에서 자료를 옮기는 요구가 생길 때. 어떤 표현을 보존할지 별도 범위로 정한다.

## Still-rejected alternatives

- 기존 보관함을 백업으로 교체하기 — 복원 전에 추가한 자료를 잃을 수 있다.
- 노트 이름이나 원본 식별자로 덮어쓰기 — 이름이 같아도 다른 노트일 수 있고 다른 계정으로 옮기기도 어렵다.
- 공유 열쇠를 그대로 복사하기 — 복원한 자료가 사용자의 의사와 무관하게 공개될 수 있다.
