# 노트 형식

## Decisions

- 노트는 일반 문서, Markdown, 그림판 세 형식 중 하나를 가진다. 노트를 만들 때 고른다.
- 형식은 만든 뒤에 바꾸지 않는다. 형식을 바꾸는 기능도, 변환 도구도 두지 않는다.
- 그림판의 그림은 요소 목록으로 보관한다. 자유 선, 사각형, 원, 선, 화살표, 글상자가 각각 하나의 요소다. 되돌리기와 다시 실행은 작업 단위로 동작한다. 요소 추가 한 번과 지우개 드래그 한 번을 각각 한 작업으로 묶고, 지우기 직전의 요소와 순서를 복원한다. 되돌린 뒤 새로 편집하면 다시 실행할 작업은 비운다.
- 그림판 지우개는 클릭하거나 누른 채 움직여 경로에 닿는 요소 전체를 지운다. 선택 중에는 그림면의 포인터를 지우개 모양으로 표시한다.
- 그림판은 작업 영역을 채우며, 여유 공간에도 그릴 수 있다. 창 크기가 바뀌면 그림·글자·선 굵기를 같은 배율로 표시하고 저장된 좌표와 굵기는 바꾸지 않는다. 이미 그린 범위가 화면보다 크면 스크롤로 접근한다.
- 그림판 굵기는 Thin, Normal, Thick, Extra thick에 해당하는 언어별 이름으로 표시한다. 화면 픽셀 수로 오해하지 않도록 숫자와 px는 표시하지 않는다.
- 일반 문서의 서식은 인라인 style로 저장한다. 서식 메뉴는 저장된 그 값을 되읽어, 지금 고른 글에 걸려 있는 서식을 그대로 비춘다.
- 일반 문서에 붙여넣을 때는 편집기가 지원하는 글자 서식과 목록·줄바꿈만 유지한다. 외부 문단의 배경, 여백, class는 가져오지 않는다. 서식 없이 붙여넣기도 제공한다.
- 기존 문서는 자동으로 바꾸지 않는다. 서식 지우기는 선택한 문단(목록에서는 선택한 항목)의 글자·문단 서식을 지우되 목록과 줄바꿈, 선택하지 않은 항목은 유지한다.
- 서식 메뉴가 한 번 내보낸 글꼴 값은 바꾸지 않는다. 글꼴을 늘릴 때는 줄을 더하기만 한다.
- 목록 미리보기는 형식을 따른다. 일반 문서와 Markdown은 본문 앞부분을 글로 발췌하고, 그림판은 같은 요소를 작게 다시 그린다.
- 목록의 썸네일은 그 노트의 배경을 함께 입는다. 배경을 바꾸면 여는 화면과 목록이 같은 것을 보여준다.
- 그림 요소가 어떤 도형이 되는지는 한 곳에서만 정한다. 편집 화면과 목록과 공유 화면은 그것을 React로 옮기고, 내보내기는 같은 것을 SVG 글자로 옮긴다.
- 화면 문구만 표시 언어를 따른다. 노트의 제목과 본문, 사용자가 지은 폴더 이름은 언어 설정과 무관하게 그대로 둔다.

## Boundaries

- 일반 문서의 서식은 글꼴, 글자 크기, 글자 색, 글자 배경색, 굵게, 기울임, 밑줄, 취소선, 글머리·번호 목록, 좌·가운데·우 정렬까지다. 글자 배경색은 선택한 글에 적용하며 노트 전체의 배경과는 별개다. 표, 이미지 삽입, 링크는 넣지 않는다.
- 글꼴은 기기에 있는 것에 기댄다. 노트 본문을 위해 웹폰트를 따로 받아오지 않는다.
- 서식 메뉴가 넣지 않은 값은 되읽지 않는다. 붙여넣기로 들어온 낯선 글자 크기는 기본 크기로 보여 준다.
- 그림판의 원점은 고정하고 오른쪽·아래쪽의 그려진 범위에 맞춰 그림면을 확장한다. 수동 배율 조절과 무한 캔버스 탐색은 범위 밖이며, 작업 영역에 따른 자동 배율만 지원한다. 공유·목록·내보내기도 기존 그림면 밖의 요소를 표시한다.
- 그림판 작업 이력은 현재 노트를 열어 둔 동안만 유지한다. 자동 저장 뒤에도 이력을 유지하지만, 새로 열거나 브라우저 초안·다른 기기의 최신 내용을 불러오면 그 내용을 새 시작점으로 삼는다. 전체 수정 이력의 영구 보관은 별도 범위다.
- 형식을 더하는 일까지 막지는 않는다. 막는 것은 이미 만든 노트의 형식을 바꾸는 일이다.

## Why

세 형식은 표현할 수 있는 것이 서로 다르다. 형식을 바꾸면 내용이 소리 없이 손실되는 경우가 생긴다. 그림판의 도형을 Markdown으로 옮길 방법이 없고, 일반 문서의 서식을 Markdown이 모두 담지도 못한다. 변환을 지원하는 순간 "어디까지 옮겨지는가"를 형식 조합마다 정의해야 하고, 사용자는 잃을 것을 예측할 수 없다.

그림을 이미지 한 장으로 남기면 이어 그리기와 요소 단위 되돌리기가 성립하지 않는다. 제품이 "다시 찾아 이어 쓴다"를 약속하므로 요소로 남긴다.

지우개 드래그에서 만난 요소를 각각 되돌리면 사용자가 한 번에 지운 것을 여러 번 되살려야 한다. 누르고 뗀 한 동작을 한 작업으로 묶어야 삭제 직전 상태로 돌아간다. 작업 이력을 현재 편집에 한정하면 다른 기기의 내용이나 복구한 초안을 이전 편집 이력으로 덮는 일도 피할 수 있다.

창 너비만큼 그림을 가로로 늘리면 도형이 찌그러지고, 화면상 선 굵기를 고정하면 같은 도구로 그린 선도 배율에 따라 원본 굵기가 달라진다. 원본 좌표와 굵기를 유지하면서 균일하게 표시하고 남는 곳을 그릴 공간으로 제공하면 두 문제를 피할 수 있다.

썸네일이 배경을 함께 입는 이유는 목록에서 노트를 찾는 방법이 제목만이 아니기 때문이다. 제목을 비워 둔 노트가 흔한데, 그때 배경은 사용자가 그 노트에 직접 붙여 둔 유일한 표시다. 목록만 흰 종이로 보이면 그 표시가 사라진다.

도형을 그리는 규칙을 한 곳에 두는 이유는 같은 그림이 네 곳에서 그려지기 때문이다. 규칙이 둘이 되면 화면에서 본 그림과 내보낸 파일이 조금씩 달라지고, 그 차이는 파일을 열어 보기 전까지 드러나지 않는다.

글꼴 값은 노트 본문 안에 문자열 그대로 박혀 저장된다. 되읽을 때 견주는 것도 같은 문자열이다. 그래서 값을 손보는 순간 이미 쓴 노트의 글꼴을 알아보지 못하고, 서식 메뉴는 그 글에 아무것도 걸려 있지 않은 것처럼 보여 준다. 화면에 보이는 글자는 그대로인데 메뉴만 거짓을 말하므로 알아차리기도 어렵다.

되읽기가 계산된 스타일이 아니라 인라인 style을 보는 이유도 같다. 계산된 값은 폰트 변수가 실제 이름으로 풀려 버려 우리가 넣은 값과 견줄 수 없다. 저장과 되읽기가 같은 문자열을 쓰는 동안에만 메뉴가 사실을 말한다.

노트 내용은 사용자의 것이다. 표시 언어를 바꿨다고 사용자가 쓴 글이 달라지면 그것은 번역이 아니라 훼손이다.

외부 HTML을 그대로 받아들이면 편집기가 수정할 수 없는 문단 배경까지 남는다. 붙여넣을 때 지원하는 서식으로 정리하면 가져온 글도 직접 쓴 글처럼 고칠 수 있다. 기존 문서는 사용자가 원본 모양을 유지하려 할 수 있으므로 명시적인 서식 지우기로만 정리한다.

## Reconsider when

- 같은 내용을 다른 형식으로 이어 쓰고 싶다는 요구가 반복될 때. 그때도 형식 변환이 아니라 "이 노트를 원본으로 새 형식의 노트 만들기"처럼 원본을 남기는 방식을 먼저 본다.
- 같은 노트가 기기마다 다른 글꼴로 보이는 것이 실제로 문제가 될 때. 그때도 모든 글꼴을 웹폰트로 바꾸는 것이 아니라, 기본 글꼴 한 벌만 내려받는 쪽을 먼저 본다.
- 그림이 복잡해져 요소 목록을 그대로 불러오는 것이 느려질 때. 요소 보관을 버리는 것이 아니라 미리보기용 표현을 따로 두는 쪽을 먼저 본다.

## Still-rejected alternatives

- 형식을 하나로 합치고 안에서 블록 종류를 섞기 — 형식 선택 자체가 사라져 단순해 보이지만, 편집기 하나가 세 가지 편집 방식을 모두 떠안게 된다. "형식을 골라 쓴다"는 제품의 약속과도 어긋난다.
- 노트 글꼴을 웹폰트로 내려받기 — 기기와 무관하게 같은 모양이 되지만, 글꼴 한 벌을 더 받는 값이 선택지를 넷 더하는 값보다 크다. 본문 글꼴은 사용자가 고르는 것이라 앱의 시각 정체성과도 분리된다.
- execCommand의 기본 결과(`<font>` 속성)로 저장하기 — 명령 앞에 styleWithCSS를 켜지 않으면 이렇게 된다. 저장은 되지만 인라인 style을 보는 되읽기가 함께 깨져, 서식 메뉴가 걸린 글꼴을 알아보지 못한다.
- 그림판을 PNG 한 장으로 저장하기 — 목록 미리보기는 쉬워지지만 이어 그리기와 되돌리기를 잃는다.
