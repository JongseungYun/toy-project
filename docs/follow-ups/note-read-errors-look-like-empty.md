# 노트 조회 실패가 "빈 보관함"과 "없는 노트"로 보인다

## 증상

Supabase 조회가 실패하면 사용자는 자기 노트가 사라진 것처럼 본다. 보관함은
"첫 노트를 만들어 보세요"를 띄우고, 멀쩡한 노트 주소는 404가 된다.

## 관찰한 근거

`code-review low`(태스크 02 체크포인트)가 지적했다. `lib/notes/queries.ts`의
`listNotes`는 `if (error || !data) return []`, `getNote`는 같은 조건에서
`null`을 돌려주고, `app/notes/[id]/page.tsx`가 그 `null`을 `notFound()`로
바꾼다. 조회 실패와 "정말 없음"이 호출한 쪽에서 구분되지 않는다.

## 짐작하는 원인

오류를 값으로 접어 넣어 상위에 전달하지 않는다.

## 해본 것

고치지 않았다. 태스크 02의 수용 기준을 깨지 않고, 스펙도 읽기 실패 표시를
요구하지 않아 `AGENTS.md`의 검증·리뷰 예산에서 범위 밖으로 두었다.

## 다음에 할 일

조회 결과를 `{ notes } | { error }` 같은 형태로 올려 화면이 빈 상태와 실패
상태를 갈라 보여주게 한다. 스펙의 "오류는 무엇을 하면 되는지 한 문장으로
알린다"를 읽기 경로에도 적용할지 함께 정한다.
