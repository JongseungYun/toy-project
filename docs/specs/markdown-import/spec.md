# R08 Markdown 파일 가져오기

2026-11-15 사용자가 다음 작업 진행을 요청했다. 앞서 제안한 `.md` 한 파일을 새 Markdown 노트로 가져오는 범위를 먼저 구현한다.

## 동작과 확인 기준

- 설정의 Markdown 가져오기에서 UTF-8 `.md` 파일 하나를 선택하고 가져오기를 실행한다.
- 파일명에서 `.md`를 뺀 이름을 제목으로 사용한다. 본문 원문을 보존하고 기존 Markdown 미리보기로 보여준다. UTF-8 BOM은 인코딩 표식으로 제거한다.
- 로그인한 계정의 내 노트 최상위에 새 노트를 저장하고 해당 편집 화면을 연다. 기본 배경은 계정 설정을 따른다.
- 빈 파일도 빈 노트로 열 수 있다. 대문자 `.MD` 확장자도 받는다.
- 같은 이름으로 다시 가져오면 별도 노트를 만든다. 같은 요청의 저장 응답을 잃어 재시도하면 이미 생성한 노트를 연다.
- 파일 형식·인코딩·크기 오류와 저장 실패를 화면에 표시한다. 저장 실패 후 같은 파일로 재시도할 수 있다.
- 가져온 원문은 재열기·수정·검색·공유·내보내기의 기존 Markdown 흐름에서 사용할 수 있다.

## 구현 시 정한 가정

- 설정의 백업·복원 카드 옆에 같은 형태의 카드를 추가한다. 기존 설정 화면 구성을 재사용한다.
- 파일 하나의 최대 크기는 512 KiB로 시작한다. 현재 서버 액션의 기본 요청 제한 안에서 파일과 요청 정보를 처리할 수 있게 한다.
- 이미지·링크 주소는 원문에 보존한다. 파일과 함께 있던 로컬 이미지의 업로드 및 상대 경로 재작성은 추후 범위를 정한다. 선택 화면에 첨부 이미지가 별도라는 안내를 제공한다.
- HTML, ZIP, 여러 파일 및 폴더 가져오기는 후속 범위다.

## 검증 결과

2026-11-16 실제 Supabase와 Chrome에서 파일 가져오기·재열기·수정·내보내기·검색·공유·같은 이름 재가져오기를 확인했다. 390px 화면의 오류 안내와 빈 파일 가져오기, 저장 응답 유실 뒤 재시도도 통과했다. 서버 액션에서 파일과 UTF-8을 다시 검사하며 노트 생성에는 로그인 계정의 RLS를 사용한다. 타입·변경 파일 lint와 Next.js 컴파일·런타임 검사를 통과했다. 호출 가능한 자동 코드 리뷰 도구가 없어 자동 리뷰는 미실시했다. 실제 휴대폰의 파일 선택은 사용자 확인이 남아 있다.
