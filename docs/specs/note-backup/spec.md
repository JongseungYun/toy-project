# R08 전체 백업·복원

2026-11-01 사용자가 R08 진행과 기존 자료 유지·복사본 추가 방식을 확정했다.

## 사용자 결과

설정에서 아무노트 전용 백업 파일 하나를 내려받고, 같은 계정이나 다른 계정에서 파일의 내용을 확인한 뒤 복원한다. 복원한 노트는 원래 형식으로 다시 편집할 수 있다.

## 범위와 수용 기준

1. 중첩 폴더와 빈 폴더, 세 형식의 제목·본문·서식·그림 요소, 고정 상태, 노트의 배경 색·이미지를 백업하고 복원한다. 작성·수정 시각도 유지한다.
2. 휴지통에 있는 노트·폴더와 현재 보관 중인 수정 이력도 담는다. 복원 후 휴지통에서 되돌리기와 이력 복원을 사용할 수 있다.
3. 파일 선택 후 백업 시각, 폴더·노트·휴지통·이력·이미지 수와 기존 자료 유지 방식을 확인한다. 확인 전에는 자료를 쓰지 않는다.
4. 복원본은 새 복원 폴더에 추가하며 기존 노트·폴더·미저장 초안은 바꾸지 않는다. 같은 이름과 같은 백업을 여러 번 복원해도 각각 별도 복사본이다.
5. 다른 계정에서 복원해도 이미지와 내용은 복원한 계정만 접근한다. 계정 정보·공유 열쇠를 담지 않으며 현재 계정의 언어·기본 배경 등 설정도 바꾸지 않는다.
6. 손상된 파일, 지원하지 않는 버전, 빠진 이미지·잘못된 참조는 복원 전에 안내한다. 요청 실패는 재시도할 수 있고 자료는 중간 일부만 생성하지 않는다. 응답 유실 뒤 동일 요청을 재시도하면 이미 완료된 결과로 돌아간다.
7. 백업용 이미지나 조회 하나라도 실패하면 불완전한 파일을 성공으로 내려주지 않는다. 빈 보관함도 정상적인 백업으로 구분한다.
8. 좁은 화면에서 파일 선택·확인·복원·결과를 사용할 수 있다. 백업은 서버 저장본을 담고 미저장 초안은 포함하지 않는다는 안내를 표시한다.

- [note-backup](../../decisions/note-backup.md): 포함 범위, 복사본 추가, 계정·공유 권한 분리.
- [note-safety](../../decisions/note-safety.md): 초안·충돌 보호, 소유자 권한, 휴지통과 수정 이력.
- [note-formats](../../decisions/note-formats.md): 형식과 원본 표현 유지.
- [note-sharing](../../decisions/note-sharing.md): 기존 개별 내보내기와 공유 동작 유지.

## 조정 가능한 기본값과 제외 범위

- 날짜가 든 이름의 ZIP 파일에 버전이 있는 전용 명세와 이미지를 함께 담는다. 압축 파일 64MiB·펼친 자료 128MiB까지를 초기 지원 한도로 둔다. 넘으면 일부만 빼지 않고 안내한다.
- 복원 폴더 이름은 표시 언어의 복원 문구와 실행 시각으로 만든다. 새 복사본은 공유를 끈 상태로 시작한다.
- 계정 설정·비밀번호·공유 링크·미저장 브라우저 초안·사용하지 않는 이미지 파일, 외부 앱 파일 가져오기·형식 변환·기존 자료 교체는 제외한다.
- 앱이 지원하는 본문 서식은 보존한다. 실행 코드가 섞인 파일은 본문으로 실행하지 않는다.

## 구현·검증 결과

2026-11-01 사용자가 [백업 SQL](../../../supabase/migrations/20261101132221_note_backup.sql)을 Cloud에 적용했다. 백업 메타데이터는 소유자의 한 DB 스냅샷에서 읽고, 배경 이미지 실물과 무결성 검사용 값을 ZIP에 함께 담는다. 폴더·노트·수정 이력은 하나의 트랜잭션에서 새 ID로 추가한다. 요청별 완료 기록을 사용해 응답 유실 후 재시도를 중복 생성과 구분한다.

- [파일 검증](../../../lib/notes/backup-file.test.ts) 10개: 한글·서식·이미지 왕복, 누락된 참조·중복 ID·잘못된 본문과 버전·이미지 손상·지원 버전·크기·순환 폴더를 확인했다. 파일에서 들어온 일반 문서는 파서로 지원 서식만 남긴다.
- [실제 Cloud 검증](../../../e2e/backup.spec.ts) 3개: 다른 계정으로 중첩·빈 폴더와 세 형식·고정·이미지·휴지통·수정 이력을 복원했다. 원본과 기존 계정 노트·설정 유지, 비공개 이미지 권한, 복원 후 이력 복원·Markdown 편집·그림 요소 추가, 휴지통 그룹 복구, 같은 파일의 별도 재복원을 확인했다. 빈 백업·사전 확인 취소·잘못된 파일·320px 화면과 비로그인 API도 검증했다.
- [실패 검증](../../../e2e/read-errors.spec.ts)의 R08 1개: 메타데이터 조회와 이미지 다운로드 실패에는 불완전한 파일을 내려주지 않는다. 복원이 DB에 반영된 뒤 응답만 유실되는 상황에서 재시도해도 복사본과 이미지 업로드가 늘지 않는 것을 확인했다.
- 기존 로그인·공유·세 형식 개별 내보내기 6개 브라우저 흐름과 임시 PostgreSQL의 5개 검증 묶음이 통과했다. 비로그인 API가 로그인 HTML을 파일처럼 받지 않도록 인증 오류 응답을 분리했다.
- `fflate@0.8.3`의 공식 README와 정확한 버전을 임시 환경에서 확인한 후 고정했다. 설치된 Next.js의 Route Handler·Proxy 문서와 현재 Supabase Storage·함수·SSR 문서를 대조했다.
- 타입 검사·앱/테스트 린트·Next.js 컴파일 및 런타임 진단이 통과했다. 호출 가능한 자동 코드 리뷰 도구가 없어 별도 자동 리뷰는 미실시했다. 전체 린트의 기존 스킬 fixture 문제는 [기존 후속 기록](../../follow-ups/skill-fixtures-in-global-lint.md)을 따른다.
