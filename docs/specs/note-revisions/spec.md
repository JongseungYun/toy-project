# R06 수정 이력·이전 버전 복원

2026-11-01 사용자가 노트당 최근 50개, 기간 제한 없음 정책을 확정하고 구현을 요청했다.

## 해결할 상황

본문을 실수로 고친 뒤 자동 저장까지 끝나거나 노트를 다시 열었어도, 이전 내용을 확인하고 되살릴 수 있다. 현재 그림판의 세션 내 되돌리기와 별도로 서버에 복원 지점을 남긴다.

## 범위

- 일반 문서·Markdown·그림판 모두 제목과 본문을 보관·복원한다. 본문의 서식과 그림 요소도 포함한다.
- 노트 머리말의 수정 이력에서 시각과 제목으로 복원 지점을 고르고 내용을 읽기 전용으로 미리 본다.
- 복원 전 현재 편집 내용을 먼저 안전하게 저장한다. 최신 내용도 이력에 보존한 뒤 선택한 과거 내용을 새 버전으로 복원한다. 복원한 작업 자체도 다시 이전 상태로 돌아갈 수 있다.
- 저장 실패·연결 끊김·미해결 충돌 상태에서는 복원을 진행하지 않는다. 복원 중 다른 기기가 먼저 저장했다면 중단하고 최신 상태를 확인한다. 다른 내용을 조용히 덮지 않는다.
- 폴더 위치·고정 여부·노트 전체 배경·공유 설정은 현재 값을 유지한다. 노트 형식도 바꾸지 않는다.
- 이력은 해당 노트의 소유자만 읽고 복원할 수 있다. 공유 링크에는 이력을 노출하지 않는다.
- 휴지통으로 보낼 때는 이력을 유지하고 노트를 복원하면 다시 사용할 수 있다. 노트를 영구 삭제하면 이력도 함께 삭제한다.
- 기능 적용 이후부터 이력을 남긴다. 기존 노트는 다음 편집 직전 상태부터 보관할 수 있으며, 이미 사라진 과거 내용까지 재구성하지는 않는다.

## 보관 정책

- 기존 자동 저장 간격은 유지한다.
- 이력은 약 5분 간격으로 묶어 복원 지점을 남긴다. 첫 편집 전 상태와 복원 직전 상태는 간격과 관계없이 보존한다. 변경이 없는 저장과 고정·폴더·공유 설정만 바뀐 경우에는 본문 이력을 늘리지 않는다.
- **노트당 최근 50개 복원 지점을 기간 제한 없이 보관한다.** 50개를 넘으면 오래된 지점부터 정리한다. 현재 노트의 내용은 이 제한으로 삭제하지 않는다.
- 개수 제한은 자료량을 제한하고, 기간 제한을 두지 않는 것은 자주 수정하지 않는 노트의 이력이 날짜만 지나 사라지지 않게 하려는 선택이다. 오래 편집한 노트는 50개 제한으로 과거 복원 지점이 더 빨리 빠질 수 있다.

5분 묶음의 최신 지점은 새 저장에 따라 교체될 수 있다. 미리 본 지점이 교체되거나 보관 한도로 사라졌으면 다른 내용을 대신 복원하지 않고 목록을 새로 확인하게 한다.

## 수용 기준

1. 세 형식의 제목·본문을 바꾸고 노트를 다시 열어도 이전 내용을 미리 보고 복원한다.
2. 복원 직전의 최신 내용도 남아 있어 과거 내용을 되살린 작업을 다시 되돌릴 수 있다.
3. 저장 대기·실패·연결 끊김·다른 기기의 수정 중에도 현재 내용과 브라우저 초안이 사라지지 않는다.
4. 고정·이동·노트 배경·공유 설정을 바꿔도 본문 이력이 불필요하게 늘지 않고, 본문 복원으로 설정이 되돌아가지 않는다.
5. 다른 계정과 비로그인 요청은 이력을 읽거나 복원할 수 없다. 휴지통 복원 뒤 이력이 유지되고 영구 삭제 뒤에는 이력도 남지 않는다.
6. 선택한 간격·보관 정책과 경계값이 실제로 적용되며, 조회·복원 실패는 재시도할 수 있다.
7. 좁은 화면에서 이력 선택·미리보기·복원이 가능하다.

## 제외 범위

- 글자 단위 변경점 비교, 작성자별 추적, 여러 버전 자동 병합.
- 폴더·고정·배경 이미지 파일·공유 링크 설정의 과거 상태 복원.
- 전체 백업과 외부 파일 가져오기(R08), 그림판 세션 내 작업 이력 규칙 변경(R12).

## 구현·검증 결과

2026-11-01 사용자가 [이력 SQL](../../../supabase/migrations/20261101124523_note_revisions.sql)을 Cloud에 적용했다. 노트의 저장과 같은 트랜잭션에서 이전 내용을 기록하고, 소유자의 버전 확인·행 잠금·복원 직전 보관을 거쳐 복원한다. 5분 묶음에서 교체되는 지점은 새 ID를 사용하므로 미리 본 ID가 다른 본문을 가리키지 않는다.

- [이력 검증](../../../e2e/note-revisions.spec.ts) 6개: 세 형식의 서식·그림 미리보기와 복원·복원 취소·재진입·후속 편집, 320px/오프라인 초안, 두 기기 충돌, 실제 Cloud API의 소유자 권한·설정 보존·최근 50개·교체된 지점·휴지통·영구 삭제를 확인했다.
- [실패 검증](../../../e2e/read-errors.spec.ts)의 R06 1개: 목록·미리보기 조회 실패와 복원 실패를 각각 주입하고 현재 내용 유지와 재시도를 확인했다.
- 자동 저장 훅 테스트 14개와 기존 R01·R02·모바일 편집 9개 브라우저 흐름을 확인했다. 임시 PostgreSQL에서도 5분 경계·기간 제한 없음·삭제 연쇄를 포함한 10개 검증 묶음을 실행했다.
- 타입 검사와 앱/테스트 린트, Next.js 컴파일·런타임 진단을 확인했다. 호출 가능한 자동 코드 리뷰 도구가 없어 별도 자동 리뷰는 미실시했다. 전체 린트의 기존 스킬 fixture 문제는 [기존 후속 기록](../../follow-ups/skill-fixtures-in-global-lint.md)을 따른다.
